# apps/slides

チームCのスライド。[Slidev](https://sli.dev/) で Markdown から作る。

| ファイル | 用途 |
| --- | --- |
| `onboarding.md` | **メンバー向け。** 前半＝全体像（全員）／後半＝開発者向け |
| `pitch.md` | **発表用。** ハッカソンの発表（持ち時間 7 分・未確定） |

**`onboarding.md` は 400 行を超えているが、デッキとしては分けない**（決定済み・2026-09-15）。
分けると入口ページにリンクが3つ並び、**全員向けの前半を読んだ人が後半に辿り着けたか分からなくなる。**
1本にしておけば「途中から開発者向け」と口頭で言うだけで済む。
**`layout: section` の区切りスライドが、その境目**である。
| `components/` | 図。デッキから `<ArchitectureDiagram />` のように書いて使う |
| `setup/mermaid.ts` | Mermaid の色。図の色はここ1箇所 |
| `style.css` | スライドの色とフォント |

## 動かす

```sh
pnpm dev          # onboarding.md を開く
pnpm dev:pitch    # pitch.md を開く
```

**ブラウザは自動では開かない。**表示された URL を自分で開く（`-o` を付けると開く）。
開いたまま `.md` を編集すると、画面にそのまま反映される。
`pnpm build` で `dist/` に書き出し、デプロイは担当者が `pnpm deploy:cf` で行う。

## 書き方

`---` だけの行がスライドの区切り。区切りの直後に YAML を置くとそのスライドの設定になる
（**ファイル先頭の YAML だけはデッキ全体の設定**で、`title:` や `theme:` はそこに書く）。

````md
---
layout: center     ← このスライドの設定
---

# 見出し

本文。HTML も書ける。

---

# 次のスライド
````

書ける記法の一覧は [Slidev のドキュメント](https://sli.dev/guide/syntax)。

## 図の作り方（3つ）

**上から順に試して、足りなければ下に降りる。** 下にいくほど自由度が上がり、手間も増える。

| 手法 | 向いているもの | 例 |
| --- | --- | --- |
| **1. Mermaid** | 流れ・順序。箱と矢印で済むもの | `onboarding.md`「開発の進め方」 |
| **2. HTML + UnoCSS** | 並べて比べるもの。カード・段組み。**見た目を細かく決められる** | `components/ArchitectureDiagram.vue` |
| **3. 手書き SVG** | 時間の流れ・重なり・道のような「絵」。HTML の箱では表せない形 | `components/HeartbeatTimeline.vue` |

**2つ以上のデッキで使う図は `components/` に置く。** 1つでしか使わないならスライドに直接書いてよい。

### 1. Mermaid — 速い

` ```mermaid ` のコードフェンスに書けば図になる。**差分がテキストとして読める**のが利点。

- **色は `setup/mermaid.ts` で揃える。** 既定の黄色い箱はスライドから浮く
- **`fontFamily` に `inherit` を書かない。** 文字の幅を測れず、箱から文字がはみ出す
- **矢印の向きが箱の並びを決める。** 左から右に読ませたいなら、左の箱から書く
- **図の中の要素を1つずつ出すこと（`v-click`）はできない。** 必要になったら 2 か 3 に降りる

### 2. HTML + UnoCSS — 見栄え重視の既定

普通の HTML を書いて、[UnoCSS](https://unocss.dev/) のクラスで見た目を決める。
`v-for` や `v-if` も使えるので、同じ形のカードを並べるのが楽。

- アイコンは `<div class="i-tabler-bike" />` のように書く（[一覧](https://icones.js.org/collection/tabler)）。
  **別のアイコンセットを使うなら `@iconify-json/<名前>` を入れる**
- 色は `var(--slidev-theme-primary)`。直接 `#0d9488` と書かない
- **スライドの幅は 980px 相当。** 超えたぶんは警告も出ずに切れるので、必ず画面で確かめる

### 3. 手書き SVG — 最後の手段

- **`font-size` は属性ではなく `<style>` で書く。** スライド側の CSS（`font-size: 80px`）が
  属性に勝つため、`font-size="20"` と書いても効かない
- **`viewBox` はスライドに置いたときの実寸に近い値にする**（幅 1000 前後）。
  小さくすると文字だけが引き伸ばされて他の要素と重なる

### 見た目

色とフォントは `style.css` だけにある。レイアウトには手を入れない
（作り込むほど `theme:` を差し替えられなくなるため）。

**「どこで処理が起きるか」は色で示す。** `style.css` に3つ置いてある。

| 変数 | 意味 |
| --- | --- |
| `--layer-device` | 自転車の上の装置の話 |
| `--layer-mobile` | スマホの話（`--slidev-theme-primary` と同じ色） |
| `--layer-cloud` | 向こう側（Worker）の話 |

- **デッキ全体で同じ意味で使う。** 装置の話に `--layer-cloud` を当てない。
  色が揃っていないと、読み手は色を手がかりにするのをやめる
- **箱の上辺に 3px の線として入れるのが既定**（`ArchitectureDiagram.vue` と
  `onboarding.md`「5つの検知」が同じ書き方をしている）
- **ダークモードは使わない。** 各デッキの headmatter に `colorSchema: light` を書いてある。
  **`dark:` のクラスをスライドやコンポーネントに書かないこと**——2色ぶん確かめる手間が倍かかるうえ、
  投影は明るい画面が既定なので、暗いほうは結局ほとんど見られない

日本語フォントは OS に入っているものだけを並べている（`style.css`）。
**発表当日にネットが無くても日本語の見た目が変わらない**ようにするため。
テーマ自体は欧文フォントを Google Fonts から読むが、日本語のグリフを持たないので日本語には効かない。

### 動画

デモ動画の置き場所は `public/demo/`。スライドからは **`/` で始まるパス**で参照する。

```md
<video src="/demo/xxx.mp4" controls />
```

- **`demo/xxx.mp4` や `./demo/xxx.mp4` と書くとビルドが落ちる。** Vite が取り込む対象として
  解決しようとして見つけられない。`/` で始めれば配信先に合わせて書き換えてくれる
  （`/pitch/demo/xxx.mp4` になる）
- **ファイルが無い状態でタグだけ先に書かない。** 同じ理由でビルドが落ちる
- `public/` のファイルは**デッキごとの出力に同じものがコピーされる**
  （`dist/onboarding/` と `dist/pitch/` の両方に入る）

### 書かないもの

**しきい値・GPIO のピン番号・API の形といった具体値は、なるべく書かない。**
それらの正本は `docs/` にあり、スライドに写すと必ず片方が古くなる。
「ここに数字を書きたい」と思ったときは、たいてい**リンク先を読んでもらう場面**。

（禁止ではない。書いたなら、元が変わったときに直す。）

## Lint の設定を分けている理由

`biome.json` をこのパッケージに置いて、`correctness/noUnusedVariables` だけ切っている。
**Vue の `<script setup>` で宣言した変数を `<template>` で使っても、Biome は使用を追えず「未使用」と言う。**
警告のまま置くと `pnpm lint:fix` が消しにいく。

- ルートの `overrides` で `**/*.vue` だけに絞るのを先に試したが、
  **`overrides` を足した瞬間に `apps/device/.venv` まで走査されるようになった**ので、
  パッケージ単位のファイルに分けた
- **この `biome.json` にコメントを書かないこと。** 書くと直後の `"root": false` が無視され、
  「ルート設定が2つある」というエラーで CI が落ちる（コメントの有無だけで再現する）

## 残っている作業

**未完のスライドは `# TODO: <伝えたいこと>` の見出しとして、そのまま残してある。**
別のファイルに作業リストを作らない（スライドを開けば必ず目に入るが、別ファイルは読まれない）。

残りの枚数は数えられる。

```sh
grep -c '^# TODO' onboarding.md pitch.md        # macOS / Git Bash
Select-String -Pattern '^# TODO' *.md | Measure-Object   # PowerShell
```

**いま残っているのは `pitch.md` の4枚だけ**（課題 / 誰のどんな瞬間か / 今後 / まとめ）。
`onboarding.md` にあった「なぜ岡山 × 自転車なのか」は落とした（決定済み・2026-09-15）——
**メンバー向けは「何をつくっているか」から入るほうが速く、課題の背景は発表で語ればよい**ため。

半日以上かかるものだけ Issue にする（`CLAUDE.md`「深掘りしすぎない」）。

**`pitch.md` のデモのスライドは `# TODO` に数えていない。**
形（実機・画面切り替え・動画）が決まっていないだけで、スライド自体は最終形のため。

## デッキを増やすとき

**`.md` をこのディレクトリの直下に作るだけ。** 設定を足す必要はない
（`scripts/build.mjs` が直下の `*.md` を数えてビルドし、入口ページも作り直す）。

- Slidev は**エントリの `.md` があるディレクトリ**をプロジェクトルートとして扱う。
  サブフォルダに入れると `public/` も `style.css` も `components/` も読まれなくなる
- **ビルドはデッキごとに `--base /<名前>/` を付けて実行している。** 付けないと資産を
  `/assets/...` に取りにいき、`/onboarding/` で配信したときに真っ白になる
  （`--router-mode hash` が直すのは経路であって資産の場所ではない）
