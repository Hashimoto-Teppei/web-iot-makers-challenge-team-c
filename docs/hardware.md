## 搭載するモジュール

部品を足したら**この表と下のピン割り当て表の両方**に行を足す。片方だけ更新すると必ずずれる。

| モジュール | 型番 | 接続 | ピン / アドレス | 用途 | 状態 |
| --- | --- | --- | --- | --- | --- |
| 表示 | LCD1602A + I2C シリアル変換基板（PCF8574） | I2C | `0x27`（**または `0x3F`**。下記） | 走行中の記号表示（上段）と `link`/`mv`（下段）、停止中の情報表示 | 予約 |
| 音 | 自励式ブザー（+ NPN トランジスタ + ベース抵抗） | GPIO 1本 | GPIO17（物理 11） | 気づかせる | 予約 |
| 光 | LED ×1（+ 電流制限抵抗） | GPIO 1本 | GPIO22（物理 15） | 音を補う（走行風と騒音で音が届かないときの警告） | 予約 |
| 後方物体検知 | AE-NJR4265 J1（NJR4265 J1 / 24GHz ドップラー） | GPIO 1本 | GPIO27（物理 13） | 後方から接近する物体の検知（#26） | 予約 |

**4つとも 5V 系の信号を GPIO に入れない形で載せる。** 詳しくは下の各項。

**GPS モジュール（GY-GPSV3-NEO6M）は載せないことにした**（`adr/0004-v2v-transport.md`）。
位置はスマホから来る。**配線とピン割り当ては git の履歴に残っている**ので、戻す判断をしたときは
このファイルの1つ前の版を見ること。

**載せると決まったものだけを書く。** 使うかどうか自体を検討している段階のものは、この表に入れず
アイデアの Issue で管理する（ウインカー #24 / ブレーキランプ #25。**どちらも `deferred`**）。

### 表示 — LCD1602A（I2C 変換基板つき）

16文字×2行のキャラクタ LCD。表示できるのは**英数字と半角カタカナだけ**で、**漢字は出せない**
（`notifications/arbitration.md`「画面の割り付け（16×2）」）。**上下段に何を出すかもそこで決まっている。**

**配線は SDA / SCL / VCC / GND の4本だけ**（変換基板がはんだ付け済みの製品を使う）。

**まず 3.3V で駆動する。** 変換基板のプルアップ抵抗が VCC につながっているため、
**5V で駆動すると SDA / SCL に 5V が乗り、GPIO を壊す**（`adr/0003`）。3.3V なら直結できる。

**ただし HD44780 系は 3.3V ではコントラストが出ないことがある**（暗くて読めない）。
そのときは **5V 駆動 + I2C の双方向レベル変換モジュール**に切り替える。
**部品を1つ足すだけで、ピンの割り当ては変わらない**（`unverified.md` 93）。

**I2C アドレスは実機で確定する。** 変換基板のチップが PCF8574T なら `0x27`、
PCF8574AT なら `0x3F` で、**見た目では分からない**。`i2cdetect -y 1` で1回見て、
`config.py` の `LCD_I2C_ADDRESS` に入れる。

### 後方物体検知 — AE-NJR4265 J1

24GHz 帯のマイクロ波ドップラーセンサー。**接近と離反を区別して、それぞれデジタル出力に出す**
（データシート Rev.05j「6.1. 接続端子」）。**日本向けの J1 タイプは工事設計認証済み**（ARIB STD-T73）。

**UART を持っているが、使わない。** このモジュールは UART（9600bps）でも検知結果を通知でき、
キットには USB 変換も載っているが、**接近の検知出力を GPIO 1本で読めば足りる。**
UART を使えば **Bluetooth と取り合いになる**（下の「UART を使う部品を載せるとき」）ため、
**GPIO14/15 にはつながない。** ここを間違えると、BLE ——警告と心拍の唯一の経路—— が詰まる。

**離反の出力（端子6）も使わない。** 遠ざかる物体は危険ではない。
**GPIO 1本で済ませ、必要になったら1本足す。**

**VDD は 3.3V にする。** 動作範囲は 3.0〜5.25V だが、**検知出力は CMOS で、H のときに VDD がそのまま出る。**
5V で駆動すると 5V が GPIO に乗って壊れる（`unverified.md` 28。**配線する前にテスターで測る**）。

**検知距離は基板の半固定抵抗 VR1 で決める**（`検知距離 = VTH / VDD × 10m`、約 0.7〜10m）。
**この値はコードの設定に出せない。**`config.py` にあるのは GPIO 番号だけで、
**距離はツマミの位置が正本**である。デモの距離に合わせたら、その値をここに書く（未調整）。

| 項目 | 値 | 出典 |
| --- | --- | --- |
| 検知可能速度範囲 | **0.25 〜 1.0 m/s** | データシート「4. 検知性能」 |
| 検知可能角度 | ±35°（アンテナ半値幅は H 面 70° / V 面 54°） | 同上 |
| 最大検知距離 | 10m（VR1 で調整） | 同上 |
| 消費電流 | 60mA（移動体検知モード） | データシート「2. 電気特性」 |

**速度範囲が自転車に合っていない。** 0.25〜1.0 m/s は時速 0.9〜3.6km で、**歩く速度向けの人感センサー**である。
**後方から来る自動車（約 11 m/s）も自転車（約 4 m/s）も範囲の外**にある。
**デモの条件（止まった自転車の後ろから人が歩いて近づく）はちょうど範囲の中**なので、
**この部品で進める**が、実走行では出ない可能性がある（`unverified.md` 92）。

### 光 — LED 1個

`notifications/arbitration.md` の `light` チャンネル。**`lv` に応じて点滅・点灯する**
（0.5Hz / 2Hz / 点灯）。**音が届かない場面を補うのが役割**なので、ブザーを外しても LED は残す。

**LED 1個は抵抗を経由して GPIO に直結してよい**（`adr/0003`。複数個やブザーはトランジスタが要る）。

### 音 — 自励式ブザー

**音程を作らない自励式（能動）ブザーを使う。** `notifications/arbitration.md` の `tone` は
**「100ms を何回」しか指定しておらず、周波数を指定していない**ので、
**音程の出せないブザーでも仕様どおりに鳴らせる。**PWM も専用ピンも要らない。

**GPIO から直接駆動しない。** NPN トランジスタとベース抵抗を挟む（`adr/0003`）。

**ブザーの + 側は 5V（物理ピン 2）から取る。** 3.3V より大きな音が出せて、
**トランジスタが間に入るので 5V が GPIO に乗ることはない。**
3.3V レールに載せない理由はもう1つあり、**あちらは既に 90mA 前後を抱えている**（`unverified.md` 94）。

**つなぎ方（ロウサイド・スイッチ）** —— **ブザーの + を 5V、- をトランジスタのコレクタへ。**
エミッタを GND（物理ピン 14）、ベースを抵抗経由で GPIO17 へ。
**5V をブザーの - 側やベースにつながないこと。**

**外すのは `config.py` の `BUZZER_GPIO` を `None` にするだけ**でよい（下記）。

### 載せない・外すの切り替え

`config.py` の4つの値で、**部品が載っていない状態をそのまま表せる**ようにしてある。

```python
LCD_I2C_ADDRESS: int | None = 0x27  # None で表示しない
LIGHT_GPIO: int | None = 22         # None で光らせない
BUZZER_GPIO: int | None = 17        # None で音を出さない
REAR_SENSOR_GPIO: int | None = 27   # None で後方検知を止める
```

**`enabled` のフラグを別に持たない。** 1つの値で切れる方が、読む場所が増えない。
**実機を持たない開発者が動かすときも同じ経路**で、4つとも `None` にすれば
ハードウェアに触らずに起動できる（`adr/0002-development-lifecycle.md`）。

### I2C アドレス

I2C は1本の線に複数の部品をぶら下げられるが、**アドレスが重なると両方動かなくなる**。
部品を選ぶ前にここを見て、重複しないことを確認する。

| アドレス | モジュール | 状態 |
| --- | --- | --- |
| `0x27` **または** `0x3F` | LCD1602A の I2C 変換基板（PCF8574T なら `0x27` / PCF8574AT なら `0x3F`） | 予約（**実機の `i2cdetect -y 1` で確定する**） |

同じアドレスの部品を2つ使いたい場合は、変更ピンで別アドレスにするか I2C マルチプレクサが要る（未検討）。

### UART を使う部品を載せるとき

**GPIO14/15 は空いているが、ただの空きピンではない。** Zero W では既定で Bluetooth が
性能の良い方の UART（PL011）を使っており、GPIO に出ているのは簡易版（ミニ UART）である。
ここに連続してデータが流れる部品（GPS・レーダー・シリアルのセンサー）を載せると、
**Bluetooth と取り合いになる。**

**BLE はいま警告の唯一の出口**（`interfaces/v2v.md`）なので、以前より痛い。
判断はスマホで行われるため、**BLE が詰まるとデバイスは警告を出せず、心拍も途切れる**
（`adr/0006-decision-layer-on-mobile.md`）。位置が通らなくなった代わりに、**止まったときの見え方が悪くなった。**
UART の部品を候補に挙げた時点で `adr/0003` の「UART を使う部品は Bluetooth と競合する」を読み、
**3つの選択肢のどれを採るかを先に決めてからピンを予約すること。**

**いま載っている部品に UART を使うものは無い。** ただし **AE-NJR4265 は UART も持っている**ので、
**「シリアルの口があるから挿す」をしないこと。**この部品は検知出力を GPIO で読む（上）。

## 測位はスマホが行う

デバイスに GPS モジュールを載せない（`adr/0004-v2v-transport.md`）。
**位置はデバイスに届きもしない。** 判断がスマホへ移ったため、位置を使うのはスマホの中だけである
（`adr/0006-decision-layer-on-mobile.md`）。

**それでもここに書くのは、測位性能が検知の前提そのものだから**であり、
デバイス担当が部品を選ぶときに知っておく必要があるためではない。**これは端末と置き場所で変わる。**

| 項目 | 見込み | 効いてくるところ |
| --- | --- | --- |
| 更新頻度 | **1Hz**（`FusedLocationProvider` に 1000ms を要求） | 時速 20km で**1秒あたり約 5.5m 進む**。急接近の検知には粗い |
| 水平位置精度 | **端末が `Location.getAccuracy()` でメートルで返す。値をそのまま使う** | 換算も係数も要らない。1通ごとに `hacc` として運ぶ（`interfaces/v2v.md`） |
| 置き場所の影響 | **ポケットや鞄の中では大きく劣化する** | **ハンドルにマウントし、画面は消す**運用を前提にする（`unverified.md`） |
| 起動から測位まで | A-GPS があるので通常は数秒 | 電源を入れ直しても待たされない |

**「スマホだから高精度」とは限らない。** 多衛星系（QZSS を含む）と A-GPS で有利な一方、
アンテナは金属筐体の中の小さなもので、外付けパッチアンテナを空に向けた専用受信機より不利になりうる。
**置き場所が精度を左右する**ため、運用の前提として決めておく必要がある。

## 電源

**手持ちのモバイルバッテリーから、micro USB でラズパイの PWR IN へ給電する。**
部品はすべてラズパイのピンから取るので、**電源の系統は1つだけ**である。

**容量よりオートオフの方が問題になる。** 消費が小さいと「充電が終わった」と判断して
給電を止めるバッテリーがある。**下の見積もりは 250mA なので通常は止まらない**が、
**止まると走行中に丸ごと落ちる**ため、デモに使う個体で1回確かめる（`unverified.md` 7）。

**5000mAh なら実効で 10〜12時間。** モバイルバッテリーの容量表示は**セルの 3.7V 基準**なので、
5V に換算すると 3,700mAh 相当まで落ちる（5000 × 3.7 ÷ 5）。250mA で割って理論 **約15時間**、
昇圧の損失を見て**その 8 割程度**が実際に使える時間である。
**デモには十分なので、容量の検討はしない。**

### 消費電流の見積もり

**部品を足すたびにここへ1行足す。** 稼働時間はバッテリー容量 ÷ 合計消費電流で概算できる。
デモの途中で電池が切れるのが一番まずいので、**実測値が取れたら見積もりを実測に置き換える**。

| 部品 | 見積もり | 実測 | 備考 |
| --- | --- | --- | --- |
| Raspberry Pi Zero W（BLE 常時接続） | 150mA | — | **BLE は走行中ずっとつながっている。**アイドル時の値（約 100mA）で見積もらない |
| LCD1602A + I2C 変換基板 | 30mA | — | ほぼバックライトのぶん |
| AE-NJR4265 J1 | 60mA | — | データシート「2. 電気特性」の移動体検知モード |
| LED | 10mA | — | 抵抗で決まる。点滅なので平均はこれより小さい |
| ブザー | 30mA | — | **5V ピンから。鳴っている間だけ**なので合計には入れていない（連続では鳴らない） |
| **合計** | **250mA** | — | 5V 換算。**すべてデータシートと公表値で、実測は1つも無い** |

**実測はここでやらない。** 電流計を当てるのは実機を出す回に他の確認とまとめる
（#139「実機2台で1回走り、しきい値と連続稼働をまとめて測る」）。
**実機を出す機会は多くないので、1回にまとめる。**

## 結線表

**部品が2〜3個を超えたら、実物のどの線がどこに刺さっているかを追える形をここに置く。**
上の割り当て表は「そのピンを誰が取ったか」を答えるが、**「この部品から何本出て、どこへ行くか」には答えない。**

**4個になったので置いた。** ただし**写真や手描きの図ではなく、この表**にしている ——
**まだ配線していないので写真が撮れず**、絵は**実物と食い違ったときに更新されずに残る**ため。
**実際に配線したら、この表の「状態」を更新し、写真を1枚足す。**
