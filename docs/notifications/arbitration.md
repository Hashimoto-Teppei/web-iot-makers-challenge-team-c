# 警告の出し分け

`../notifications.md` から分割した。**元のファイルが 400 行に達したからではない**
（`CLAUDE.md` の行数の基準は発火していない）。**「なぜ・いつ出してよいか」と
「何をどう出すか」で読む人が違う**ため、決定を足す時点で分けた。
**ドキュメントは再統合のコストがほぼゼロなので、コードより早く分けてよい**（`CLAUDE.md`）。
**なぜ走行中に文章を出さないか・いつ「走行中」とするかは
[`../notifications.md`](../notifications.md) が正本**で、ここでは決め直さない。

**このファイルが決めるのは「何を、どの出力で、どう出すか」だけ。**
`kind` の識別子と `lv` の意味は [`../interfaces/detectors.md`](../interfaces/detectors.md)、
運び方は [`../interfaces/v2v.md`](../interfaces/v2v.md)「デバイスへ渡すもの」が正本である。

実装先は `apps/device/src/device/notify.py`（**ハードウェアに触らない**。
`../notifications.md`「調停はハードウェアに触らない場所に置く」）。

## 出力のチャンネル

**部品名ではなく役割で4つに分ける。** 部品は未確定（#13）だが、
**どういう区別が必要かは部品が決まる前に決められる。**

| チャンネル | 役割 | 想定している部品 |
| --- | --- | --- |
| `tone` | **気づかせる。**唯一、見なくても伝わる | ブザー ×1 |
| `light` | 音を補う。走行風と交通騒音で音が届かないことがある | LED ×1 |
| `line1`（上段16文字） | **いま何が起きているか。**1件だけ | 16×2 キャラクタ LCD |
| `line2`（下段16文字） | **仕組みが生きているか**（`link` / `mv`） | 同上 |

- **`notify.py` が返すのはこの4チャンネルへの指示まで。** GPIO と LCD を叩くのはその外側。
- **チャンネルを増やすときは役割を1つ足す。** 1つの役割を2つの部品で分け合わない
  （「どちらに出たか」を人が覚えることになる）。
- **振動は使わない。** 自転車のハンドルは走行中つねに振動しており、**警告の振動と区別できない。**
  部品も無い。**方向を伝えたくなったら `light` を増やす**（前後に置けば位置で伝わる）——
  それは #13 で部品が決まってから、この表に足す。

## 音と光は `lv` だけを表す

**`tone` と `light` は `kind` を区別しない。`lv` の3段階だけを表す。**

| `lv` | `tone`（**1回きりの発火**） | `light`（**発火中ずっと続く状態**） |
| --- | --- | --- |
| 1 | 短音 1回（100ms） | 0.5Hz の点滅 |
| 2 | 短音 2回（100ms × 2、間 100ms） | 2Hz の点滅 |
| 3 | 長音 2回（600ms × 2、間 200ms） | 点灯 |

**時間と回数は仮の値**（`../unverified.md` 45）。`config.py` に置き、実地で調整する。

**`tone` と `light` は寿命が違う。混ぜない。**

- **`tone` はイベント**である。鳴らす条件は下の「鳴らし直す条件」で決まり、**延長では鳴らない**
- **`light` は状態**である。**選ばれている警告の `lv` を毎周期そのまま出す**もので、
  発火し直すという概念を持たない。**保持が延長されている間は点き続ける**

**この2つを同じ規則で扱わないこと。** `light` をイベントにすると、
**危険が続いて再送されている `lv 3` で、最初の数秒だけ光って以後は消え**、
LCD が `!!!` を出したままになる。**音が届かない場面を補うのが `light` の役割**なので、
一番効かせたい状況で消えることになる。

**なぜ `kind` を音で分けないか。**

- **5種類の音のパターンを走行中に聞き分けることはできない。** 覚えられないパターンを増やすと、
  **どれも「何か鳴った」にしかならず**、3段階の区別まで一緒に潰れる。
- **`lv 3` に対して人がすることは `kind` によらず同じ**である（速度を落とす・止まる）。
  出し分けても行動が変わらないものを、**一番細い経路（音）で伝えない。**
- **`kind` を知りたければ止まって上段を見ればよい。** 停止中なら見てよい（下）。

**したがって「音だけで意味が区別できるか」という論点は、区別させないことで閉じている。**
音が伝えるのは「どれくらい危ないか」だけ。

## 同時に起きたときの優先順位

**発火中の警告のうち1件だけを選び、4チャンネルすべてでその1件を表す。重ねない。**

- 音は重ねると**どちらとも違う3つ目のパターン**に聞こえる
- `light` も上段も1つしかない
- **重ねられないことを認めて選ぶ規則を決める方が、実装者にとって予測できる**

**順位は次の全順序で決める。**

1. **`lv` の高い順**（3 > 2 > 1）
2. 同じ `lv` なら、**`kind` の固定順**（強い順）

| 順 | `kind` | なぜここか |
| --- | --- | --- |
| 1 | `rear_object` | **後ろは振り向かないと見えない。**他の4つは本人の目にも入りうる。加えて**通信が死んでいても出る唯一のもの**なので、これが出ているとき他は当てにできない |
| 2 | `approach` | 猶予が最も短い。相手が自分に向かって詰めてきている |
| 3 | `brake` | 前方で**すでに起きている**。ただし前方なので本人も気づける |
| 4 | `corner` | **まだ曲がり角に着いていない。**`brake` より猶予がある |
| 5 | `stop` | 標識は動かない。**猶予が最も長く、位置も予測できる** |

**これ以上のタイブレークは要らない。** 同じ `kind` が同時に2つ発火中になることはない——
検知は `kind` ごとに最大1つしか返さず（`../interfaces/detectors.md`「出力」）、
`rear_object` もデバイスの中で1つである。**同じ `kind` の `warn` が来たら、前のものを置き換える**（下）。

**選ばれなかった警告は消えない。保持したまま順位を待つ。**
上位が消えたら、残りの保持時間のあいだ表に出る。**捨てると、上位が一瞬出た隙に下位が消える。**

## 出し続ける時間と、消える条件

**「危険が去った」という通知は届かない。** 検知は「安全である」という出力を持たない
（`../interfaces/detectors.md`「「なし」は「安全」ではない」）。デバイスに届くのは発火のイベントだけなので、
**危険が去ったことを根拠に消すことはできない。時間で消すしかない。**

- 受け取った `warn` は、**`lv` ごとの保持時間**のあいだ「発火中」とする

  | `lv` | 保持時間（既定・仮） |
  | --- | --- |
  | 1 | **3 秒** |
  | 2 | 4 秒 |
  | 3 | 6 秒 |

  **`lv 1` を 3 秒にしてあるのは、下の再送間隔（2 秒）より長くするため。**
  2 秒どうしで揃えると、**保持が切れてから次の再送が届くまでの隙間で表示が消える。**
  BLE の書き込みは必ず多少遅れて届くので、これは確率ではなく**毎回起きる。**

  **この3つは走行ごとにアプリから上書きできる**（`config` の `hold1` / `hold2` / `hold3`。
  範囲 1000〜10000ms。[`../interfaces/ble-gatt.md`](../interfaces/ble-gatt.md)「`config`」）。
  **上書きしても再送間隔との関係は変わらない**ので、**`hold1` を下げるときは再送間隔も見ること。**

- **同じ `kind` の `warn` がもう一度来たら、保持時間を延長し、`lv` を新しい方に置き換える**
  （上がるのも下がるのも）。**2件に増やさない**
- 保持時間が切れたら消える。**危険が続いていればスマホが送り直す**（下）
- **人が消す操作を作らない。** ボタンで消す設計にすると、**押す動作が走行中に発生する**

**既定値は仮**（`../unverified.md` 46）。`config.py` に置く。

### 送り続けるのはスマホの責務

消える条件を時間にした結果、**「危険が続いていることを伝える」責務がスマホ側に移る。**
`../interfaces/mobile-api.md`「同じ警告を毎周期書き直さない」が指しているのはこの仕様である。

- **同じ `kind` + 同じ `causeId` の警告は、`lv` が変わらない限り 2 秒に1回だけ書く**（既定・仮）
- **`lv` が上がったら、間隔を待たずに書く**
- **`lv` が下がったときは間隔を待つ。** 下がったことを急いで伝える理由が無い
- **`causeId` が変わったら別の警告として扱う**（別の相手・別の標識である）。
  **`kind` と組で見ること**——`causeId` は自転車の id と標識の id が同じ項目に入るので、
  `kind` を無視すると**たまたま一致した別物が同じ警告として抑制される**
  （`../interfaces/detectors.md`「出力」）

**再送間隔（2 秒）は、一番短い保持時間（`lv 1` の 3 秒）より短くする。既定はこれを満たしている。**
**等しくしてもいけない。** 等しいか長いと、保持が切れてから次が届くまでの隙間で
**危険が続いているのに表示が消える**（BLE の遅れがあるので、等しいときは毎回起きる）。
**片方だけ調整して、この関係を壊さないこと。**

## 鳴らし直す条件

**鳴らすのは「新しく上位になった瞬間」だけ。保持中の延長では鳴らさない。**
同じ警告が数秒おきに鳴り続けると、**人は音を無視するようになる。**

**条件は5つあり、そのすべてが「その警告について、まだ鳴らしていないか」に還元できる。**

| 起きたこと | 鳴らすか | なぜ |
| --- | --- | --- |
| 同じ `kind` が同じ `lv` のまま延長された | **鳴らさない** | 表示は出続けている。鳴らすと数秒おきに鳴り続ける |
| `lv` が上がった（`2 → 3`） | **鳴らす** | 伝える価値がある |
| `lv` が下がった（`3 → 1`） | **鳴らさない** | 下がったことを急いで伝える理由が無い |
| **一度達した `lv` に戻った（`3 → 1 → 3`）** | **鳴らさない** | 下の `peak_lv` から出る帰結。**同じ危険の中の揺れ**であって、新しく上位になったのではない。ここで鳴らすと、揺れている間ずっと鳴り続ける（保持が切れて消えれば、次に来たものは別の警告として鳴る） |
| 上位が消えて、**すでに鳴った**下位が表に戻った | **鳴らさない** | 同じ警告を2度鳴らすことになる |
| 上位に隠れている間に届き、**一度も鳴っていない**下位が表に出た | **鳴らす** | まだ発火中＝危険は続いている。ここで黙ると一度も伝わらない |

**したがって、鳴らすかどうかは「いま選ばれているもの」だけでは決まらない。**
どの警告について何を鳴らしたかを覚えている必要がある。
**「前回の出力と比べる」では表現できない**——上位が消えて下位に戻ったとき、
前回の出力と比べれば必ず変わっているので、**鳴ってはいけない場面で鳴る。**

### 鳴らしたことを鍵の集合で持つ

**`arbitrate()` に「これまでに鳴らした鍵の集合」を渡し、更新したものを返させる。**
状態を引数と戻り値で受け渡すので、**関数は純粋なまま**であり、pytest で確かめられる。

**鍵の作り方。**

| 鳴らすもの | 鍵 |
| --- | --- |
| 警告 | `"{kind}:{peak_lv}:{peak_at_ms}"` |
| 通信断 | `"link:down:{link_since_ms}"` |

**`peak_lv` は、その警告が発火してから達した最大の `lv`。`peak_at_ms` はそれになった時刻。**
`lv` そのものを使わないのは、**下がったときに鍵が変わって鳴ってしまう**ため。
最大値なら下がっても動かない。

**毎周期、次の順にやる。**

1. **候補の鍵を作る。**発火中の警告それぞれの鍵と、`link` が `down` なら通信断の鍵
2. **鳴らすのは、候補のうち渡された集合に無いもの。**1周期に1つだけ鳴らす
   （2つ以上あれば通信断を先に。下）
3. **返す集合は「渡された集合のうち、今回も候補だったもの」に、
   実際に鳴らしたものの鍵を足したもの**

**3 が全部を成立させている。** 順に確かめられる。

| 起きること | どうなるか |
| --- | --- |
| 保持時間が切れて警告が消えた | 候補から外れる → 集合から落ちる。**溜まらない** |
| `lv` が上がった | 鍵が変わる。**古い鍵はもう候補でないので落ちる** |
| `link` が `up` に戻った | 通信断の鍵が候補から外れて落ちる。**次に落ちたときはまた鳴る** |
| 同じ警告が延長され続ける | 候補のまま、集合にも残る → **鳴らない** |
| 上位に隠れて鳴らせなかった警告 | **鳴らしていないので集合に入らない。**表に出た周期で鳴る |

**集合の大きさは候補の数を超えない。** 足すだけの作りにすると走行中ずっと増え続けるので、
**毎周期、生きているものだけに絞り直す。**

**「鳴らしたものだけを足す」を崩さないこと。** 発火中のものを一律に足すと、
**上位に隠れて鳴らせなかった警告が、鳴らないまま鳴ったことにされる**——
`../adr/0006-decision-layer-on-mobile.md` が一番恐れた「静かに止まる」の小さい版になる。

**`tone` は1周期に1つしか返さない。** 鳴らすものが2つ重なったら
**通信断のチャイムを先に出し、警告のチャイムは次の周期に回す。**
回した警告は**鳴らしていないので集合に入らず**、次の周期でそのまま鳴る（上の表の最後の行）。
通信断を後回しにしないのは、**`link` が落ちたことに気づかせるのが `../adr/0006` の成立条件**
だからである（`../interfaces/v2v.md`「心拍を必ず見せる」）。**1周期は 1 秒未満なので、
どちらも鳴る。**

**`light` はこの規則の対象外。** 上の「音と光は `lv` だけを表す」のとおり状態であり、
毎周期そのまま出す。

## 画面の割り付け（16×2）

**部品そのものは未確定**（#13。`../hardware.md` の「搭載するモジュール」が正本で、そこでは「未定」）。
**16×2 のキャラクタ LCD を前提に設計する**ことは決定済みで、この前提が文言の設計を縛る。

**表示できるのは英数字と半角カタカナだけで、32文字。**
16×2 のキャラクタ LCD は HD44780 互換が大半で、内蔵フォント（A00 ROM）に**漢字は無い**。
カスタム文字は 5×8 ドットで8文字まで登録できるが、**それで漢字を読める形にするのは無理がある。**
**したがって「止まれ」は漢字で出せない。**
**実装を始める前にこれを知らないと、フォントを探して時間を溶かす。**

**上下段に役割を固定して割り当てる。** 一瞥で読めることの条件は、文字が大きいことではなく
**毎回同じ場所に出ること**である。出る場所が変わると、**探すために画面を見続けることになり**、
それがこのファイルが避けようとしている「注視」そのものになる。

| 段 | 役割 |
| --- | --- |
| 上段 | **警告。**優先順位で選ばれた1件だけ |
| 下段 | **状態。**`link` と `mv`。**警告に譲らない** |

**実装のたびに空いている行へ出す、という書き方をしない。**

### 上段 — 警告

```
桁     0123456789012345
発火中 !!! REAR
なし   （16文字すべて空白）
```

| 桁 | 内容 |
| --- | --- |
| 0〜2 | **`lv` のバー。**`!` を `lv` の数だけ。残りは空白（`!  ` / `!! ` / `!!!`） |
| 4〜7 | **`kind` の記号**（4文字固定、左詰め） |
| 8〜15 | **常に空白。**警告はここを使わない |

| `kind` | 記号 |
| --- | --- |
| `rear_object` | `REAR` |
| `approach` | `APPR` |
| `brake` | `BRK ` |
| `corner` | `CRNR` |
| `stop` | `STOP` |

- **記号は英大文字に揃える。半角カタカナを混ぜない。** `トマレ` だけカナにすると
  **そこだけ「読む」動作が要る。** 5つとも同じ文字種・同じ4桁なら、**桁の形だけで見分けられる**
- **`lv` を数字で出さない。** `!` の本数は**長さとして見える**ので、読まずに量が伝わる
- **記号を増やすときは4文字に収める。** 収まらない名前を付けない

**走行中に上段へ文章を出さない。** 上の書式は記号であって文章ではない
（固定の桁に固定のトークンが出るだけで、読む対象が増えない）。

### 下段 — `link` と `mv`

```
桁       0123456789012345
走行中   OK    >
測位待ち NOFIX >
断線     DOWN  >
停止中   OK    -  （8桁目以降に情報）
```

| 桁 | 内容 |
| --- | --- |
| 0〜4 | **`link`。**`OK   ` / `NOFIX` / `DOWN ` |
| 6 | **`mv`。**`>`（走行中） / `-`（停止中） |
| 8〜15 | **停止中のみ、Worker から来た情報。走行中は空白** |

- **下段を警告に使わない。** 通信断は走行中ずっと出続けるもので、警告と場所を取り合った時点で
  **どちらかが消える。** 消えるのはたいてい常時表示の方であり、**それが一番消してはいけないもの**
  （`../interfaces/v2v.md`「心拍を必ず見せる」）
- **`up` のときも `OK` を出し続ける。空白にしない。**
  空白は「壊れて何も出ていない」と区別できない
- **`link` の桁は絶対に動かさない。** ここが動くと、探すために画面を見ることになる

### 停止中の情報表示

- **停止中で、発火中の警告が1件も無いときだけ**、
  **上段の16桁すべて**と**下段の 8〜15 桁**を情報に開放する（合わせて24文字）。
  **上段は警告のときと違って桁を割らない**——読む相手が停止しているので、
  「毎回同じ場所」の制約は掛からない
- **警告が入ったら情報は消える。**警告が消えても**情報を再表示しない**
  （戻ってきた文章を読み始めたところで走り出す形になる）
- **「もう出さない」は停止するたびに解除する。** 一度走り出して、また止まったら出してよい。
  **この「この停止中に警告が出たか」を覚えるのは呼び出し側**で、
  `arbitrate()` には真偽値で渡す（下の「調停の関数の形」）——
  関数の中に持たせると、前回の呼び出しを覚えることになる
- **下段の 0〜6 桁は開放しない。** 状態の枠は停止中も動かさない

## 通信断の見せ方

**車車間の検知はスマホの中で動き、スマホ経由の通信に依存する**
（`../adr/0004-v2v-transport.md` / `0006-decision-layer-on-mobile.md`）。
経路が死んでも、**スマホが落ちても**、**自分だけが静かに警告を受け取れなくなり、
他の全員からは正常に見える。判断そのものが向こう側へ移ったぶん、`0004` の時点より重い。**

**`link` は下段の 0〜4 桁に常時出す**（上の「下段」）。それに加えて、

- **`down` に落ちた瞬間だけ、`lv 1` と同じ音を1回鳴らす。** 以後は鳴らさない。
  **警告が発火中でも鳴らす**——`tone` が警告に占有されていたら、
  **通信断のチャイムを先に出し、警告のチャイムを次の周期へ回す**
  （上の「鳴らしたことを鍵の集合で持つ」）。
  **後方物体の警告が出ている最中にスマホが落ちるのは、まさに起こりうる形**であり、
  ここで黙ると `../adr/0006` の成立条件が満たせない
- **`nofix` では鳴らさない。** **屋内では `nofix` が出続けるのが正常**であり
  （`../interfaces/v2v.md`）、鳴らすとデモの間ずっと鳴る
- **`nofix` から `down` に落ちたときも鳴らす。** 人がすべきことが変わる
  （待つ → 端末を見る）
- **`down` から復帰したときは鳴らさない。** 表示が `OK` に戻れば足りる
- **電源を入れた直後に1回鳴るのは、そのままでよい。** `link` は `down` から始まるので
  （`../interfaces/v2v.md`「`up` から始めない」）、スマホが繋がる前に1回鳴る。
  **鳴らないようにしない**——走り出す前にブザーが生きていることが分かる唯一の機会であり、
  **鳴らない故障に自分で気づけるのはここだけ**である

**「一度きりの通知にしない」に反しない。** 消えないのは**表示**の方である。
音を鳴らし続けると、**警告の音が埋もれる**——警告は音でしか伝わらないので、そちらを守る。

**これは警告ではない**（危険が起きたわけではない）。**優先順位の表に入れず、上段も奪わない。**
**デバイスの後方物体検知は `link` に関係なく動き続ける**ので、そちらの警告は止めない。

## 調停の関数の形

```python
def arbitrate(
    warnings: Sequence[ActiveWarning],  # 発火中の候補。保持時間の判定はこの中で行う
    link: Link,                         # "up" / "nofix" / "down"
    link_since_ms: int,                 # いまの link になった時刻。down のチャイムの鍵に使う
                                        # （`up` に戻ると鍵が候補から外れ、次に落ちたときまた鳴る）
    moving: bool,                       # 直近の beat の mv（link が up でなければ True）
    info: str | None,                   # 停止中に出す情報。出さないときは None
    now_ms: int,                        # いま。**中で time を呼ばない**
    chimed: frozenset[str],             # すでに鳴らした鍵。前回の戻り値をそのまま渡す
    config: NotifyConfig,               # 保持時間・音の長さ・記号
) -> Output: ...
```

```python
@dataclass(frozen=True)
class ActiveWarning:
    kind: str
    lv: int
    expires_at_ms: int   # 保持時間の切れる時刻。同じ kind の warn が来るたびに伸びる
    peak_lv: int         # この警告で今までに達した最大の lv（鍵に使う）
    peak_at_ms: int      # peak_lv になった時刻（同上）


@dataclass(frozen=True)
class Output:
    line1: str               # 16文字。右は空白で埋める
    line2: str               # 16文字
    tone: Tone | None        # この周期で鳴らすもの。None は無音
    light: LightPattern      # **状態。**毎周期の現在値であって、イベントではない
    chimed: frozenset[str]   # 更新した鍵の集合。次の呼び出しにそのまま渡す
```

- **ハードウェアに触らない。** 引数も戻り値も値だけ。`config.py` から読むのも呼び出し側
- **`now_ms` を引数で受ける。** 中で `time.monotonic()` を呼ぶと、
  **同じ入力で結果が変わってテストが書けない**（`../interfaces/detectors.md` の `now` と同じ理由）
- **保持時間の切れた警告を落とすのもこの関数の中。** 呼び出し側は持っているものを渡すだけにし、
  **消える規則を2か所に置かない**
- **状態は引数と戻り値で受け渡す。** `chimed` を関数の中に溜め込まない。
  こうすると**同じ入力から同じ出力が出る**ので、
  「延長では鳴らない」「上位が消えて戻っても鳴らない」を pytest で確かめられる
  （`../adr/0002-development-lifecycle.md`）
- **`info` を出すかどうかの判断は呼び出し側。** 「この停止中にすでに警告が出た」という記憶を
  関数に持たせず、**出さないと決めたなら `None` を渡す**（上の「停止中の情報表示」）

**呼び出し側が持つのは3つだけ**——`ActiveWarning` のリスト、`chimed`、`info` を出してよいか。
**それ以外の記憶を増やさないこと。** 増やすほど、出力が「前に何が起きたか」に依存して
再現できなくなる。
