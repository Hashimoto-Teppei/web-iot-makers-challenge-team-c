# 危険検知アルゴリズム

`../interfaces.md` から分割した。**境界の一覧と、他の境界へのリンクは
[`../interfaces.md`](../interfaces.md) にある。**

3つの車車間の検知（#9 / #10 / #11）と一時停止の事前通知（#27）を
**別々の担当が並行実装する**ための共通インターフェース。**実装先は `apps/mobile`（TypeScript）**
であって `apps/device` ではない（`../adr/0006-decision-layer-on-mobile.md`）。

**入力のペイロードは [`v2v.md`](./v2v.md)「メッセージ」が正本。** 緯度・経度・速度・進行方角・
水平精度・時刻の形と単位はそちらで確定しており、**ここで決め直さない。**

**検知の結果をどう人に伝えるかは [`../notifications.md`](../notifications.md)。**
ここが決めるのは**検知の入口と出口の形**だけで、どの出力に割り当てるか・
同時に出たときにどれを優先するかは決めない（#29）。

## 入力を受けて結果を返す純粋な関数にする

**検知は関数1つである。** クラスにもオブジェクトにもしない。

```ts
type Detector<C> = (input: DetectorInput, config: C) => Warning | null;
```

- **ハードウェアにも通信にも触れない。** 測位の読み取り・BLE の書き込み・HTTP・
  React Native の API を検知の中に書かない。書くと開発機（Windows / macOS）で
  テストできなくなり、**実機が揃うまで誰も検証できないもの**になる
  （`../adr/0002-development-lifecycle.md`）
- **`Date.now()` を呼ばない。** 「いま」は入力（`now`）で受け取る。
  検知の中で現在時刻を取ると、**同じ入力を渡しても結果が変わり、テストが書けない**
- **乱数を使わない。前回の呼び出しを覚えない**（下の「状態を持たない」）

**この形を守れているかは Vitest で確かめられる。** モックデータだけで発火するケースと
しないケースの両方が書ければ守れている。**書けなければ、どこかで外の世界に触っている。**

## 入力

**4つの検知がすべて同じ入力型を受け取る。**

```ts
type Fix = {
  t: number;           // 測位した時刻（UTC ミリ秒）。打ったのは測位した端末の時計
  rxAt: number;        // この測位を手にした時刻（UTC ミリ秒）。打つのは自分の時計
  lat: number;         // 緯度（度、WGS84）
  lon: number;         // 経度（度、WGS84）
  spd: number;         // 対地速度（m/s）
  crs: number | null;  // 進行方角（度、真北 0、時計回り 0〜360未満）。低速時は null
  hacc: number;        // 水平位置精度（メートル）
};

type Track = {
  id: string;              // 端末ID（16進の小文字8文字）。自車は自分の id
  fixes: readonly Fix[];   // 古い順。末尾が最新。空にしない
};

type StopSign = {
  id: string;
  lat: number;
  lon: number;
};

type DetectorInput = {
  now: number;                    // 自分の時計の「いま」（UTC ミリ秒）
  self: Track;                    // 自車
  peers: readonly Track[];        // 近傍の他車。空でありうる
  signs: readonly StopSign[];     // 近傍の一時停止の標識。空でありうる
};
```

**`Fix` は [`v2v.md`](./v2v.md) の `self` / `peer` から `k` と `id` を落とし、
`rxAt` を足しただけのもの。** 別の形を作っていない。
**単位も m/s と度のままで、ここで換算しない。**

**`rxAt` は経路を通らない。受け取った側が打つ。**
`peer` では**レスポンスを受け取った時刻**、`self` では**測位を受け取った時刻**である
（`self` は自分の測位なので `t` とほぼ同じになるが、**同じ形に揃えておく**——
検知が `self` と `peer` で違う書き方をしなくて済む）。

- **使わないフィールドがあってよい。** 急接近（#9）は `signs` を見ないし、
  一時停止の事前通知（#27）は `peers` を見ない。**それでも入力型を分けない**——
  呼び出し側が4つを同じ形で回せることの方が、使わない項目が入っていることより価値がある。
  **4つ目の検知が増えたときも、入力型に足すだけで既存の検知は変わらない**
- **`peers` が空でも呼ぶ。** 空を「相手が居ない」と読み替えないこと（下の「なしは安全ではない」）
- **`signs` には近傍の標識だけを入れる。** 岡山県ぶんを毎秒渡さない。
  絞るのは呼び出し側の責務で、検知は渡されたものを全部見てよい。
  **どこから標識を得るかは未確定**（#7。[`mobile-api.md`](./mobile-api.md) 末尾）
- **`now` は自分の時計。** `self.fixes` の最新の `t` ではない。
  測位が止まっている間も `now` は進むので、**「最後の測位から何秒経ったか」が検知の中で分かる**

**時刻が2つあるのは、`t` と `rxAt` が別の時計で打たれているからである。使い分けを間違えない。**

| 何を出すか | 使う値 |
| --- | --- |
| **その位置が何秒前のものか**（外挿・古さの重み付け） | **`now - rxAt`** |
| **同じ `Track` の中の2点の間隔**（速度差から減速度を出す） | **`t` の差** |

- **`now - peer.t` を計算しない。** `t` は相手の端末の時計で打たれている。
  [`v2v.md`](./v2v.md) が失効の判定に `t` を使うことを禁じているのと同じ理由で、
  **時計がずれている端末は、常に未来か過去に居ることになる。**
  **`rxAt` は自分の時計なので、誰の `Track` でも引き算できる**
- **`t` の差は使ってよい。** 同じ端末の中の2点なら、**時計のずれは引き算で消える。**
  減速度（#10）はこれで出す。**`rxAt` の差で出さないこと**——
  経路の詰まりで到着が固まると、**止まっていないのに減速して見える**
- **`rxAt` を「いま」の代わりに使わない。** 経過は必ず `now` から測る。
  `peers` の中で一番新しい `rxAt` を「いま」にすると、**相手が全員居なくなった瞬間に時間が止まる**
- **[`v2v.md`](./v2v.md)「受信側（モバイル）の約束」8 が求める補正はここで行う。**
  経路の遅れ（150〜350ms）は `now - rxAt` に含まれている

## 出力

```ts
type Warning = {
  kind: WarnKind;      // 何の検知か
  lv: 1 | 2 | 3;       // 強さ
  causeId?: string;    // 発火の原因になったもの（相手の id / 標識の id）
};
```

**警告が無ければ `null` を返す。** 空配列でも `{ fired: false }` でもない。

- **1回の呼び出しで返すのは最大1つ。** 複数の相手が同時に該当したら、
  **`lv` が高いもの、同じなら近いもの**を1つ選んで返す。
  **デバイスの出力は1組しかない**ので、同じ `kind` を2つ渡しても出せるものは増えない
- **`causeId` は BLE を通らないし、D1 にも入らない。**
  [`v2v.md`](./v2v.md)「デバイスへ渡すもの」の `warn` は `kind` と `lv` だけであり、
  `detections` の列にも無い（[`web-service.md`](./web-service.md)）。
  **スマホの中で、同じ相手の警告を抑制するためだけに持つ**
  （抑制の仕様は [`../notifications.md`](../notifications.md)）
- **`causeId` は「相手の id」とは限らない。** 車車間の3つでは `Track.id`
  （16進の小文字8文字）が入り、一時停止の事前通知では **`StopSign.id`** が入る。
  **形式の違う2つの ID が同じ項目に入る**ので、
  **抑制する側は `kind` と組にして扱うこと**——`kind` を無視して ID だけで突き合わせると、
  たまたま一致した標識と自転車が同じものとして抑制される

### `kind` の一覧

**識別子はここが正本。** どの出力にどう割り当てるかは
[`../notifications.md`](../notifications.md)（#29）。**一覧を両方に書かない。**

| `kind` | 何 | 出どころ | Issue |
| --- | --- | --- | --- |
| `approach` | 急接近する自転車 | スマホ | #9 |
| `brake` | 前方車両の急ブレーキ | スマホ | #10 |
| `corner` | 見えない曲がり角の対向車 | スマホ | #11 |
| `stop` | 一時停止の標識が近い | スマホ | #27 |
| `rear_object` | **後方から接近する物体** | **デバイス**（ローカル検知） | #26 |

**`rear_object` だけは BLE を通らない。** デバイスの中で発生し、デバイスの中で他の警告と合流する
（`../notifications.md`「調停はハードウェアに触らない場所に置く」）。
**それでも同じ一覧に載せているのは、出力を取り合う相手だから**である。
**スマホ側の実装がこの値を送ることは無い。**

**この値の正本は [`ble-log-transfer.md`](./ble-log-transfer.md)「検知ログの `body`」**
（デバイスが吐く側にある）。ここに写しているのは一覧のためで、
**食い違ったらあちらを正とする。** `detections` の行として D1 に入るのも同じ値である
（[`web-service.md`](./web-service.md)）。**短く `rear` と書き換えないこと**——
**同じ検知が2つの名前で D1 に入り、種別ごとの集計が割れる。**

### `lv` の意味

| `lv` | 意味 |
| --- | --- |
| 1 | **気づいてほしい。**まだ余裕がある |
| 2 | **対処が要る。**速度を落とす・進路を変える |
| 3 | **直ちに危険。**間に合わないかもしれない |

**どの状況を何段階目とするかは各検知が決め、しきい値として外に出す**（下）。
**ここで決めるのは段階の意味だけ。**

**`lv` を「確からしさ」に使わない。** 測位が粗くて自信が無いことを `lv 1` で表すと、
**余裕のある危険と、危ないかもしれない危険が同じ表示になる。**
確からしさで出す・出さないを決めるのは検知の中の話で、**出すと決めたなら危険さで段階を付ける。**

## しきい値は設定として注入する

**コードに直書きしない**（`CLAUDE.md`）。**検知は第2引数で自分の設定を受け取る。**

```ts
// detect/approach.ts
export type ApproachConfig = {
  warnDistanceM: number;      // この距離まで詰まったら見る
  closingSpeedMps: number;    // 接近速度がこれを超えたら発火
  // …
};

export const approachDefaults: ApproachConfig = { /* … */ };

export const detectApproach: Detector<ApproachConfig> = (input, config) => { /* … */ };
```

- **設定の型と既定値は、その検知のファイルに置く。** 1か所にまとめない。
  **まとめると、4人が同じファイルを編集して必ずコンフリクトする**
- **既定値はすべて仮の値**である。実走行で調整する（`../unverified.md` 5）
- **設定を検知の中で書き換えない。** 読むだけ。
- **共通のしきい値を作らない。** 「接近」の意味は検知ごとに違う。
  同じ名前の値を共有すると、片方の調整がもう片方を壊す

## 状態を持たない

**履歴は呼び出し側が持ち、`Track.fixes` として渡す。**
検知がモジュール変数や引数のオブジェクトに前回の値を溜め込まない。

**なぜ呼び出し側か。**

- **[`v2v.md`](./v2v.md)「受信側（モバイル）の約束」が、近傍の状態を保つ責務を
  すでに呼び出し側に置いている。** 履歴だけ別の場所に置く理由が無い
- **4つの検知が同じ履歴を必要とする。** 各自が持つと同じものが4組でき、
  **どれが最新かが場所によって違う**状態が生まれる
- **検知が状態を持つと純粋関数でなくなり、テストが「呼ぶ順番」に依存する。**
  発火しないケースを書いたつもりが、前のテストの残りで発火する

**保つ長さは設定にする（既定 5 秒）。** 減速度を出すには数点要るが、
長く持つほど**古い点を含んだ平均が鈍る。** 既定は仮の値（`../unverified.md` 36）。

**`fixes` を空にしない。** 空の `Track` を作るくらいなら、その `Track` を `peers` に入れない。

**自車の測位が無い間は、検知を1つも呼ばない。** 空の `self` を渡さない。
[`v2v.md`](./v2v.md)「受信側（モバイル）の約束」7 が同じ状態で `peer` を持つことを禁じており、
**4つの検知はどれも自車の状態を入力に取る**ので、呼んでも `null` しか返らない。
**このとき人に見えるのは `beat` の `st: "nofix"` である**（[`v2v.md`](./v2v.md)「心拍を必ず見せる」）。

## 「なし」は「安全」ではない

**`null` は「危険が無い」ではなく「この検知は何も言えない」である。**

POST が失敗して近傍が空の間、測位が粗すぎて判断できない間、検知は `null` を返す。
**これを「周りは安全」と読み替えると、`0004` と `0006` が一番恐れた形になる**——
**自分だけが静かに警告を受け取れなくなり、他の全員からは正常に見える。**

**したがって検知は「安全である」という出力を持たない。**
分からないことを人に伝えるのは**心拍と `link` の仕組み**であって、検知ではない
（[`v2v.md`](./v2v.md)「心拍を必ず見せる」）。**検知の側にその責務を持ち込まない。**

**`crs` が `null` の相手を捨てない。** 止まっている・低速の自転車がそれであり、
**急接近（#9）が一番見たい相手がこれ**である。向きが要る計算ができないだけで、
距離と相対速度は出せる。捨てると**検知が静かに効かなくなる。**

## 呼び出し側の手順

**測位が更新されるたび（実質 1Hz）に、4つを順に呼ぶ。**

1. 近傍と履歴を更新する（[`v2v.md`](./v2v.md)「受信側（モバイル）の約束」）
2. `DetectorInput` を1つ作る
3. **4つの検知を呼び、`null` でない結果を集める**
4. 集まったものを **`lv` の高い順**に `alert` へ書く（[`v2v.md`](./v2v.md)「デバイスへ渡すもの」）

- **レジストリを作らない。** 4つを配列に詰めて回す仕組みを用意するより、
  **呼び出し側が4行書く方が読める。** 設定の型が検知ごとに違うので、
  配列にすると型が合わず、`any` を挟むことになる。5つ目が増えたら1行足す
  （`CLAUDE.md`「早すぎる抽象化を避ける」）
- **スマホ側で1つに絞らない。** 発火したものは全部送る。
  **後方物体（`rear_object`）と合流させて調停するのはデバイス**であり
  （`../notifications.md`）、**スマホは `rear_object` の存在を知らない。**
  ここで絞ると、デバイスから見て「起きなかったこと」になる
- **`lv` の高い順に書くのは、詰まったときに重要なものが先に届くようにするため。**
  優先順位を決めているのではない（それは #29）
- **同じ警告を毎周期書き直さない。** 抑制の仕様は
  [`mobile-api.md`](./mobile-api.md)「スマホの約束」と `../notifications.md`

## ファイル構成

**検知は1つ1ファイル。** 別々の担当が並行して書くための境界である。

```
apps/mobile/src/detect/
  types.ts          共通の型（Fix / Track / DetectorInput / Warning / Detector / WarnKind）
  geo.ts            距離・方位の計算（共通）
  approach.ts       急接近（#9）
  hard-brake.ts     前方急ブレーキ（#10）
  blind-corner.ts   見えない曲がり角の対向車（#11）
  stop-sign.ts      一時停止の事前通知（#27）
```

- **`types.ts` と `geo.ts` は #8 の実装で先に置く。** 決めただけでは並行開発は始まらない。
- **`geo.ts` を先に用意するのは、4つとも距離と方位を必要とするため。**
  「2つ目の利用者が現れるまで共通化しない」の例外にあたる——
  **利用者が4人いることが最初から分かっており**、各自が書くと**4通りの距離計算**ができる。
  内容は2点間の距離（メートル）と方位角、角度差の正規化まで。**それ以上を入れない**
- **他人のファイルを編集しない。** 共通のものが要るなら `geo.ts` か `types.ts` に足し、
  **PR で他の3人に伝わる形にする**（`CLAUDE.md`）
- **テストは検知と同じ名前で並べる**（`approach.test.ts`）。
  発火するケースとしないケースの両方を、**合成したモックデータ**で書く
  （実走行の GPS ログをコミットしない。`CLAUDE.md`）
- **型の正本は `types.ts` になる。** 実装が入ったら、このファイルの型はそのときの記録として残し、
  **食い違ったら `types.ts` を正とする**（[`mobile-api.md`](./mobile-api.md) と同じ立場）

## シミュレータとの関係

**検知は、データがどこから来たかを知らない**（[`v2v.md`](./v2v.md)「シミュレータ・検知との関係」）。
シミュレータ（#12）は `DetectorInput` を組み立てて渡す側であり、**検知の中には入らない。**

**シミュレータが再現すべき故障は [`v2v.md`](./v2v.md) が持つ。**
検知の側で用意するのは、**その故障が起きたときに `null` を返すことのテスト**である。
