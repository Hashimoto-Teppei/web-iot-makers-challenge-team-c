# 蓄積したデータの見せ方（画面）

**走行後に集まったものを、人が見る形にするところ。**
[`web-service.md`](./web-service.md) から分割した（画面と、データの側で担当が分かれるため。
`CLAUDE.md`「`src/client/` と `src/worker/` を混ぜない」）。
**境界の一覧は [`../interfaces.md`](../interfaces.md)。**

**何をどう数えるか（セル・率・不停止）は [`web-stats.md`](./web-stats.md) が正本。**
ここに書くのは**それをどう見せるか**だけで、**指標の定義を書き写さない。**

## 画面

**2つ。** ハッカソンなので作り込まない（`../adr/0002-development-lifecycle.md`）。

| 画面 | 中身 |
| --- | --- |
| **マップ + ランキング** | 1ページ。左に地図、右に順位表。**同じデータの2つの見せ方**として並べる |
| **場所の詳細** | 1つのセルの内訳。**時間帯ごとに**何の種類が何件、通過が何走行ぶん |

**ログインを置かない。** 誰でも見られる。書き込みの経路も認証を持たない（[`web-service.md`](./web-service.md)「割り切っていること」）。

### マップとランキングを1ページに並べる理由

**地図だけだと「どこが一番危ないか」が分からない。** 濃い円が3つあっても、順位は読み取れない。
**順位表だけだと「そこがどこか」が分からない。** 緯度経度を見ても土地勘とつながらない。

**行をクリックすると地図がその場所へ飛ぶ。** 2つを別ページにすると、この往復ができない。

**ランキングの単位はセル**（[`web-stats.md`](./web-stats.md)「セルの切り方」と同じ）。**交差点の名前でまとめない**——
名前を引くデータを別に用意することになり、ハッカソンの範囲を超える。

### レイヤーを切り替える

**検知と不停止を同時に重ねない。** 同じ交差点に2つの円が重なると、
どちらの濃さを見ているのか分からなくなる。**タブで切り替える。**

### 詳細画面で時刻を丸める

**秒単位の時刻を並べない。時間帯（例: 8時台）に丸める。日付も持たない。**
**時間帯は日本時間で切る**（決定済み・2026-09-02。#87）——UTC のまま切ると、
**朝の通勤時間帯が前日の 23 時台に出る。**

**110m のセルと秒単位の時刻を時系列に並べると、1人の走行経路が復元できる。**
走る人が数人しかいないハッカソンの規模では**これは実際に起こる**ので、
`../adr/0007-keep-raw-ride-logs.md` が「セル単位に丸めれば公開してよい」とした条件が、
時刻を出した瞬間に崩れる。

**`device_id` も公開の画面に出さない。** 出すと、丸めた時間帯であっても
**同じ端末の行を拾い集めれば経路が並ぶ。**

**この画面は検知と不停止を件数で数える**（一覧は走行の数で数える。
[`web-stats.md`](./web-stats.md)「率で見る」）。**順位を付けないので、
100% を超える率を作る心配がない**——**何が何件出たか**をそのまま出す方が読める。
**通過だけは一覧と同じく走行の数**で数える。

**種別ごとの内訳と、場所が分からなかったものを見せるのもこの画面**である。
**一覧は「場所が分からなかった数」しか返さない**（`unlocated`）ので、
**何が落ちたのかを見られる場所が他に無い。**

## 画面に出す言葉

**実装側の語を画面に出さない**（決定済み・2026-09-08）。**この画面にログインは無く、
初めて開いた人がそのまま読む**ので、**コードとドキュメントで使っている語をそのまま出すと、
数字の意味がどこにも書いていないことになる。**

**ドキュメントとコードの中では今までどおりの語を使う**——正本（[`web-stats.md`](./web-stats.md)）を
言い換えると、**指標の定義が2つに割れる。** 変えるのは**画面に出る文字だけ**である。

| コード / ドキュメント | 画面 |
| --- | --- |
| セル | **区画**（寸法は「約110m四方」と語の中に畳む） |
| 率 | **危険率** |
| `hits`（出た走行） | **発生** |
| `rides`（通過） | **通行** |
| 検知 | **走行中の警告**（種別の名前は変えない。`detectors.md`） |
| 不停止 | **一時不停止** |
| レイヤー | **表示する内容** |
| サンプルデータ | **デモ用のサンプル** |

**寸法の出し方を画面で繰り返さない。** 一覧で「約110m四方」と言えば足りる。
**切り捨ての桁も、代表座標が南西の角であることも画面に書かない**——
**どちらも円を置くときの実装の都合**（上の「場所は地図が示す」）で、**読む人の判断を何も変えない。**

**`BLE` を画面に出さない。** 利用者から見えているのは**スマホと切れている**ことだけである。

**タブの説明は画面に出す**（変更・2026-09-08）。**以前は `title` 属性にしか無く、
マウスを乗せるまで読めなかった**——**タブの名前だけでは2つの差が分からない**ので、
**選んでいる方の説明を操作列の下に1行置く。**

**ヘッダー帯にはサービス名を置く**（変更・2026-09-08）。**当初はチーム名と大会名を出していたが、
初めて開いた人が帯に求めるのは「これは何のサイトか」であって、作った人の名前ではない。**
**いま出している名前は仮称**（正式名称は**未確定**）で、`src/client/App.tsx` の2行を差し替えれば済む。

**データの出どころと規模は、まだ画面のどこにも無い**（**未確定**）。
**何台・いつからの走行かが分からないと、率の重みが判断できない。**決まったら1行足す。

## 画面のトーン

**明るい・公共/啓発型**（決定済み・2026-09-02）。白とオフホワイトの2層で、
**影ではなく余白と罫線**で構造を作る。**正本は `apps/web/src/client/index.css` の
`:root` に並ぶカスタムプロパティ**で、ここには色の値を書き写さない。

**UI ライブラリを入れない**（shadcn/ui も Tailwind も StyleX も入れない。決定済み・2026-09-02）。
**画面が2つしか無く、部品ライブラリの導入コストが回収されない**（`CLAUDE.md`「早すぎる抽象化を避ける」）。
**3つ目・4つ目の画面が出て、同じ部品を作り直し始めたら、そのときに入れる。**

**日本語の Web フォントを入れない。****数百 KB を落としてから文字が出る**ので、
**見栄えを良くする目的そのものに逆行する。**各 OS の日本語フォント（`system-ui`）を使う。

**ダークモードを作らない。** 明るいトーンを決めた直後に2つ目のトーンを持つと、
**色の決定が倍に増える**（`../adr/0002-development-lifecycle.md`「細かいところを深掘りしない」）。

### 色の割り当て

**赤はデータ専用に予約する**（決定済み・2026-09-02）。

**画面の中で赤が指すのは「危ない」だけ**にする。**タブの選択やリンクを赤にしない**——
**「赤い＝危ない」なのか「赤い＝選ばれている」なのかが、画面の上で区別できなくなる。**
この画面の存在意義は危険度を伝えることなので、**一番目を引く色は主題に渡す。**

**UI のアクセントは青緑**（`--accent`）。リンク・タブの選択・フォーカスの枠がこれを使う。
**赤の補色側にあり、同じ画面に置いても混同されない。**

**率 0 のセルを赤で強めない。** 危険が1件も出ていない行が赤いと、その場で上の約束が壊れる。

**赤の実値は2箇所にある。** CSS の `--danger` と、`src/client/stats/config.ts` の
`CIRCLE_COLOR`——**円は Google Maps に直接渡すので CSS からは触れない。片方だけ変えないこと。**

## 地図の描き方

**セルごとに円を1つ置く。**

| 何を表すか | 何で表すか |
| --- | --- |
| **走行の数の多さ** | **円の半径**。ただし数そのものではなく**平方根に比例させる** |
| **率の高さ** | **色の濃さ**（塗り） |
| **そこにセルがあること** | **円の縁**。**率に関わらず一定** |
| **どれを先に見るか** | **円の重なり順**。**率の高い円ほど上** |

**「そこにセルがある」ことは縁が示す**（変更・2026-09-02）。
**塗りだけでは率の低い円が見つけられなかった**——率 0 の円は塗りの下端しか持たず、
**地との比が 1.19:1 で、地図の上でどこにあるのか分からない。**
**「率 0 のセルも薄く描く」という決定**（`src/client/stats/config.ts`）**が、
実際には「描いたことになっていない」状態**だった。
**直すのは縁であって、塗りの下端ではない**——濃さの下端を上げると**率の幅がそのぶん狭まり、
隣り合う率が今より見分けにくくなる。濃さは率だけのものにしておく。**

**率の高い円ほど上に置く**（変更・2026-09-02）。**一覧は率の降順で返る**ので、
**素直に描くと最も危ないセルが最初に作られ、いちばん下に沈む。**
半径は通過の平方根なので、**通過が多いだけの大きな円がその上に乗り、
縁が隠れるだけでなくクリックも奪う**——**一番危ないセルを地図から選べなくなる。**

**地図の配色は既定のままにしない**（決定済み・2026-09-02。`src/client/stats/config.ts` の `MAP_STYLES`）。
**Google の既定の地図は道路が黄色く**、その上に赤い円を重ねると**濃さの違いが読めない**——
**濃さが率を表している以上、これは指標が読めないのと同じ**である。彩度を落として道路を白に寄せ、
**赤い円を画面で唯一の強い色にする。**

**地図の地は、ページの背景より一段暗くする**（変更・2026-09-02）。
**当初はページの背景に近づけていたが、地図が背景に溶けて、面としてどこで始まり
どこで終わるのかが見えなくなった**——地の比が 1.02:1、枠線も 1.17:1 しかなかった。
**地図はページの中で最も暗い面**とし、**白は幹線と高速に集める。**
地が暗くなったぶん白い道路が浮き上がり、**道路網が地図の構造として読める。**
**ページ側の色（`--bg` / `--surface` / `--danger`）は動かさない**——
**上の「赤の実値は2箇所にある」に触れずに済む**のがこの直し方を選んだ理由である。

**地名・道路名のラベルは消さない。**下の「場所は地図が示す」が、**セルに読める名前を持たない**代わりに
**地図が地名を描いていること**を根拠にしている。**消すと、画面上のどこにも場所を指す言葉が無くなる。**
消すのは**店・施設（POI）のラベル、交通機関の線、国道・県道の番号標識（青い図記号）**で、
**いずれも地名ではなく、円を隠すか、円より目を引く。**

**番号標識を消したのは後からである**（変更・2026-09-02）。
**実画面では、これが画面で最も彩度の高いものになっていて、赤い円より目を引いていた**——
上の「赤い円を画面で唯一の強い色にする」が成立していなかった。
**消えるのは図記号だけで、道路名の文字は残る**ので、上の根拠（地図が場所を指す言葉を持つ）は崩れない。

**`mapId` を使うクラウド側のスタイル指定は採らない。** Google Cloud コンソールでの作業と
環境変数がもう1つ増えるのに対し、**得られる見た目は同じ**である。
**`styles` が使えなくなったら、そのときに移す**（`mapId` を渡すと `styles` は効かなくなる）。

**半径を数に比例させてはいけない。** 人は円の**面積**で量を読む。
半径を2倍にすると面積は4倍に見えるので、**2倍の場所が4倍危険に見える。**
**平方根を取ると、面積が数に比例する。**

**色に率を割り当てるのは、この2つが独立した情報だから**である。
**通過が多くて率が低い場所**（交通量が多いだけ）と、**通過が少なくて率が高い場所**（本当に危ない）を
**同じ地図の上で見分けられる。**片方だけだと、前者が上位を埋める。

## 場所は地図が示す。名前をデータベースに持たない

**セルに「岡山駅前交差点」のような読める名前を付けない。**
**逆ジオコーディングもしない**（決定済み・2026-09-01。#7）。

**当初は、標識データに入っている交差点名称を D1 に残して使う前提だった。**
その列は**原本の全行が空**で使えないと分かっている
（[`stop-signs-source.md`](./stop-signs-source.md)）。
**残った選択肢は、外部の逆ジオコーディングを呼んで住所を作ることだけ**である。**採らない。**

- **地名はもう画面の上にある。** 地図の鍵を使って地図を描いており、
  **その地図が地名と道路名を描いている。**同じものをデータベースに写し取れば、
  **地図と食い違う名前を自前で持つ**ことになる
- **住所の列は派生データなのに永続する。** セルの座標からいつでも作り直せるものを D1 に置くと、
  **どの時点の逆ジオコーディングで作られた行なのかが分からなくなる**——
  `stop_violations` にしきい値を残しているのと同じ問題を、**今度は消せない形で抱える**
- **鍵と割り当てが1つ増える。** Geocoding API は Maps JavaScript API とは別の課金対象で、
  **下の「地図の鍵」で絞った API 制限を緩めることになる**

**代わりに、順位表の行から地図へ飛ぶ**（上の「マップとランキングを1ページに並べる理由」）。
**行に出す文字はセルの代表座標**（切り捨てた緯度経度、小数第3位）で、
**これは名前ではなく識別子として出す。**土地勘と結びつけるのは地図の仕事である。

**セルの代表座標を「中心」と書かない。** 切り捨てた値はセルの**南西の角**であり、
中心ではない。**地図に円を置くときは角に置かない**——半セルぶん（緯度 +0.0005 / 経度 +0.0005）
足した点に置く。**足し忘れると、円が実際の場所から南へ 55m・西へ 46m ずれる**（岡山の緯度で）。

## 地図の鍵

**Google Maps の JavaScript API を使う。**

**ブラウザに渡す鍵は秘密にできない。** `VITE_*` はバンドルに埋め込まれ、利用者が読める
（`CLAUDE.md`）。**隠そうとせず、悪用されても損害が出ない形にする。**

- **API ごとの割り当て上限（1日あたりのリクエスト数）を設定する。**
  **予算アラートでは止まらない**——超えても課金は続く。**止まるのは割り当ての方**
- **鍵の用途を Maps JavaScript API だけに絞る**（API 制限）
- **HTTP リファラ制限をかける。** ただしこれは**ブラウザの外からは詐称できる**ので、
  上の割り当てが最後の砦になる
- **実値をコミットしない。** ローカルは `.env`（`.gitignore` に入れる）、
  デプロイ先は環境変数として設定する。**public リポジトリで一番起きやすい事故は、
  鍵を含む `.env` を commit することである**
- **秘密が要る処理は API 側に置く。** 地図の鍵以外をクライアントに渡さない
