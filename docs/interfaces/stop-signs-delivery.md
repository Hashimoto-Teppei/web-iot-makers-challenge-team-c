# 一時停止の標識をスマホに配る（#63）

`mobile-api.md` から分割した（あちらが 400 行に達したため。`../../CLAUDE.md`）。
**走行中の中継（スマホ ⇄ API）の約束は [`mobile-api.md`](./mobile-api.md) にある。**

一時停止の事前通知（#27）はスマホで判定する（`../adr/0006-decision-layer-on-mobile.md`）。
**その材料になる標識の位置を、どうやってスマホの手元に置くか。**

**[`mobile-api.md`](./mobile-api.md)「失敗したときの約束」が「POST が落ちても一時停止の
事前通知は動き続ける」と書けているのは、標識が手元にある前提を置いているから**である。**走行中に取りに行く形にすると、この行は嘘になる。**
以下はすべて、この1行を守るための決定である。

**端末側の置き方（SQLite・ファイルの分け方・引き方・同梱物の作り方）は
[`../adr/0009-on-device-storage.md`](../adr/0009-on-device-storage.md) が正本。**
**データの出どころと D1 への取り込みは
[`stop-signs-source.md`](./stop-signs-source.md) が正本。**
**このファイルが決めるのは、その2つの間——スマホと API の間を何がどう流れるか**だけである。

### 都道府県ぶんを一度に配る。地域で分割しない

**リクエストは都道府県コードだけを取る**（岡山県 = `33`）。
**位置を含めない。**「いまいる場所の周り」も「今日走る範囲」も送らない。

- **どこを走るかをサーバーに教えないため。** 周辺だけを取りに行く形は、
  **走り出す前に現在地を送る**ことになる。走行中の中継（`v2v.md`「端末IDとプライバシー」）は
  DO のメモリにしか残らず数秒で消えるが、**こちらは走行の前に、走らなくても漏れる**
- **走っているうちに手元が尽きるため。** 開始地点の周りだけを持つと、
  予定より遠くまで走った時点で標識が切れる。**そこで取りに行けるとは限らない**——
  電波が届かない場所こそ、この検知だけが残るはずの場所である
- **分割すると「どのタイルが欠けているか」という状態が端末に生まれるため。**
  欠けたまま走っても、**警告が鳴らないことと標識が無いことは区別がつかない。**
  `0004` が一番恐れた静かな部分故障がここにも生まれる

**配れるのは、D1 に取り込んだ県だけ**（いまは岡山県だけ）。
**選べるようにしたのは #71**——器だけを先に用意していたのは
「**選べるのに反映されない状態を作らない**」ためで、取り直しの処理（#76）が入って
その条件が満たされたので開けた。**選べる県の決め方は下の「どの県を選べるかはサーバーが決める」。**
**県コードは最初から経路に持たせてある**——後から足す方が高い。

**大きさは問題にならない。** 1件は id と規制地点、進入方向だけ（`StopSign`。
`../../apps/mobile/src/detect/types.ts` が正本）で百数十バイト。
**実測は岡山県 202607 で 28,651 件・JSON 4.2MB・`signs.db` 5.8MB**（2026-09-01）。
**取りに行くのは月に1回程度**なので、走行中の 1Hz の POST とは桁が違う。

### 進入方向を一緒に配る。標識は方向ごとに1件にする

**元データ（JARTIC）は、規制地点とは別に「進入方向」の座標を持っている**
（`stop-signs-source.md`）。
**この点から規制地点へ向かって走る車両**が、その規制の対象である。

**配らないと、一時停止の事前通知が対向車線と交差する道路の標識で鳴る。**
位置だけで判定すると、交差点に近づいた全員に同じ警告が出る——
#27 が「進行方角を見る」と決めているのは、この項目があることが前提になっている。

**1つの交差点に複数の進入方向がある場合、標識を方向のぶんだけ別の `StopSign` にする**
（元データは交差点単位で1レコードだが、そのまま配らない）。

- **検知が「どの方向で鳴ったか」を区別できるようにするため。** 1件に方向の配列を持たせると、
  警告の抑制キー（`causeId` は `StopSign.id`）が方向をまたいで共有され、
  **別の進入路の警告が「同じ標識」として抑制される**（`detectors.md`）
- **端末側の SQL が単純になる。** 近傍を引く条件が行ごとに閉じる

**進入方向が `null` の標識もある**（元データに登録が無い）。
**これを「全方向が対象」と読み替えない**——**配る側は区別だけを保つ。**
**拾うか落とすかは検知が決めており**（拾う。`detectors.md`「標識」）、
配る側がここで `null` を潰すと、その判断ごと消える。

**交差点名称は持っていない。** 元データの列が空だったので D1 にも入れていない
（`web-service.md`）。**走行後の画面でも読める場所は出さないと決めた**
（[`web-ui.md`](./web-ui.md)「場所は地図が示す。名前をデータベースに持たない」）。
仮に入っていても端末へは配らない——走行中のディスプレイに文章は出せず（`CLAUDE.md`）、
**数万件ぶんの文字列は同梱物をそのまま重くする。**

### 同梱を初期値にして、API では更新だけをする

**アプリには、ビルド時点の標識が最初から入っている**（`../adr/0009-on-device-storage.md`）。
**インストール直後でも、会場の電波が死んでいても、一時停止の事前通知は動く。**

**API は「更新」だけを担う。初回の取得を担わない。**
ここを取り違えると、**同梱してあるのに「まだ取得していないので黙る」実装**ができあがる。

### 取るのはアプリの起動時。走行中は取りに行かない

- **走行を始めたら標識の取得をしない。** 数 MB の取得を、1Hz の中継と同じ回線で走らせない。
  **中継が詰まれば車車間の3検知が全部止まる**——一番失いたくないものを、
  月に1回でよい更新のために危険にさらすことになる
- **取得に失敗しても走行を止めない。手元にあるものをそのまま使う。**
  標識のデータは月次でしか更新されず、**1か月古い標識でも道路の一時停止はほとんど変わらない。**
  「最新でなければ使わない」にすると、**通信が死んでいる日にこの検知まで一緒に死ぬ**
- **差分を作らない。** 更新は**丸ごと入れ替える**。
  **差分の適用は、失敗したときに中途半端な手元を残す**——
  「何割か古い標識」は、どこが古いのか誰にも分からない

### 版はサーバーが決める

**端末は、受け取った ETag をそのまま持ち、次回 `If-None-Match` で送り返す。**
変わっていなければ `304` を受け取って何も落とさない。

- **端末側で版番号を作らない。** 作るとサーバーと突き合わせられなくなる
- **同梱物にも版が入っている**ので、**一度も通信していない端末でも版が表示できる。**
  そして**同梱直後の最初の起動では `304` が返る**（無駄な数 MB を落とさない）

### 「持っていない」と「0件」を混ぜない

**標識を持っていない端末では、一時停止の事前通知は動いていない。**
これは「近くに標識が無い」と区別がつかず、**デバイスの `link` は `up`、`beat` も出ているので、
デバイスの表示では絶対に気づけない。**

**走行前の画面に、件数と版を出す**（走行中に見る前提の画面にしない。`CLAUDE.md`）。
[`mobile-api.md`](./mobile-api.md)「失敗したときの約束」で POST の連続失敗を画面に出しているのと
同じ理由で、
**静かに効かなくなるものは、走る前に人が見られる場所に出す。**

**件数が 0 なら走行を始めさせない**（`../adr/0009-on-device-storage.md`）。

### API の形

**`GET /api/stop-signs`。型はコードが正本**なので、ここに構造を書き写さない（このファイルの冒頭）。
**型から読み取れないことだけ:**

- **引数は都道府県コードだけ。位置を取らない**（上の「都道府県ぶんを一度に配る」）
- **ETag を返し、`If-None-Match` に応える**
- **認証を置かない。** 公開されている交通規制情報であり、隠す意味がない
  （`web-service.md`「割り切っていること」と同じ立場）
- **この経路は開発時にも使う。** 各自の同梱物はここから作る
  （`../adr/0009-on-device-storage.md`）。**壊すと、走行中だけでなくビルドも止まる**
- **出どころ（D1 か R2 か）はこの URL の外側の話。** 標識を D1 の外へ出すかは
  **#114 で保留**にしてある（DuckDB は却下）。**やるときも `GET /api/stop-signs` のまま
  出どころだけ差し替える**——この URL は同梱物のビルドにも使うため。判断と、開き直す引き金は #114

### どの県を選べるかはサーバーが決める（#71）

**端末に 47 県の一覧を持たせない。** 選べるのは **D1 に取り込んである県だけ**で、
それを返す口を1つ足す（`GET /api/stop-signs/prefs`）。

- **「選べるのに取れない県」を作らないため。** 取り込めるのは JARTIC の原本を持つ人だけで
  （`../../apps/web/README.md`）、**どの県が入っているかは増えていく。**
  端末に一覧を焼き込むと、**選んだ瞬間に 404 が返る県**が必ず出る
  （上の「『持っていない』と『0件』を混ぜない」と同じ話で、
  **「入っていない」と「標識が無い」を端末が混ぜる**ことになる）
- **一覧を返すのはコードと版と件数だけ。名前は返さない。**
  都道府県の名前は JIS X 0401 で固定されており変わらないので、**端末が持つ**
  ——数十バイトのために通信を1往復増やさない。
  **知らないコードを名前で騙らない**のは、いまの設定画面と同じ
- **一覧が取れないときは選ばせない。** 取れないことを画面に出し、**手元の県のまま走らせる。**
  ここで手元の県だけを並べて「選べる」ように見せると、
  **1つしか選べない理由が電波なのか取り込みなのか、誰にも区別が付かない**

### 県を選び直したときも、丸ごと取り直す（#71）

**選び直しは、起動時の更新と同じ処理を通す。**2つ作らない。

- **差分を作らない**のも、**失敗しても前の県の標識を消さない**のも、
  上の「同梱を初期値にして、API では更新だけをする」でもう決まっている。
  **入れ替えはトランザクションで囲んであり**（`../adr/0009-on-device-storage.md`）、
  途中で落ちれば1件も変わらない
- **違うのは1つだけ。「どの県を頼むか」を手元の `meta` ではなく人が決める。**
  頼む県が手元と違うときは、**`If-None-Match` に手元の版を載せない**
  ——別の県の版を送り返すことになる
- **複数の県を同時に持たない**（当面）。持つなら**どの県が欠けているか**を人に見せる必要があり、
  それは分割して配らないと決めた理由（上の「地域で分割しない」）と同じ問題を持ち込む
- **走行中は選ばせない。** 上の「取るのはアプリの起動時。走行中は取りに行かない」がそのまま効く
- **「選んだ県」を別に持たない。** 手元の `signs.db` の `meta.pref` が正本で、
  **入れ替えが成功したときだけ変わる**（`../adr/0009-on-device-storage.md`「1」）。
  別に持つと、**取り直しに失敗した端末が「選んだことになっているのに持っていない」**状態になる
  ——それは、この Issue が作らないと決めた「選べるのに反映されない」そのものである
