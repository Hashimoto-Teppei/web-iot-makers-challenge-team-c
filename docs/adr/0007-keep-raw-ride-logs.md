# ADR 0007: 走行の生ログ（測位の連続点）を保存する

- ステータス: 決定済み（**実データ未確認** → `../unverified.md`）
- 日付: 2026-08-31

## 背景

集めたデータを「どこが危ないか」として見せる Web サービスを作る（#7）。
仕様は `../interfaces/web-service.md` に書いた。

**その中で1つだけ、あとから変えるのが高くつくものがある。**
**走行の生ログ（測位の連続点）を保存するかどうか**である。

高くつく理由は単純で、**保存しないと決めた期間のデータは、あとから作り直せない**から。
実走行の機会は限られており、**取り直しが効かない。**

**集計の指標（件数か率か）・画面の構成・円の描き方・セルの大きさは、
生ログさえ残っていればいつでも変えられる**ので、この ADR には書かない
（データの側は `../interfaces/web-service.md`、画面は `../interfaces/web-ui.md` が正本）。

## 決定

**走行の測位点を、間引かず、集計してからではなく、点のまま `ride_points` に保存する。**

## なぜ

### 1. 不停止（一時停止に従わなかったこと）を、あとから何度でも計算し直せる

「何 km/h 以下なら停止と見なすか」「標識から何 m 手前を見るか」は、
**実データを見ないと決まらない。**

生ログがあれば、**データを集め直さずにしきい値を変えられる。**
集計だけを残すと、しきい値を変えるたびに**走り直しになる**——
実走行が1回しかできない可能性がある以上、これは「あとで調整する」が
「もう調整できない」と同義になることを意味する。

**これが「検知」と「不停止」を別の概念として持てる理由そのもの**である
（`../interfaces/web-service.md`「言葉」）。
**検知は端末側で確定してしまい、作り直せない。**
不停止まで同じ性質にしてしまうと、**この仕組みには調整の余地が1つも無くなる。**

### 2. 率の分母がここから来る

`../interfaces/web-service.md` は、順位を**件数ではなく率**（危険が出た走行の数 ÷ 通った走行の数）で決めている。
**その分母は走行ログを数えて作る。**

**指標を件数に変えることはいつでもできるが、その逆はできない。**
生ログを残していない期間については、分母が永久に立たない。

## 検討した案

| 案 | 判断 |
| --- | --- |
| 端末側で不停止を判定し、結果だけ送る | **却下。**しきい値が端末で確定し、作り直せない。**検知と同じ性質になってしまう** |
| セル単位に集計してから送る | **却下。**分母も不停止も作れない |
| 点を間引いて（数秒に1点）送る | **却下。**止まったかどうかが読めなくなる。**停止の判定は点の密度そのもの** |
| **生ログを送って保存する**（採用） | 作り直せる。**代償は下** |

## この決定で失うもの

**位置情報を、個人が特定できる粒度で保存することになる。**

**走行の連続点は、自宅・勤務先・行動パターンをそのまま含む。**
「どこで危険が起きたか」だけなら丸めた点で足りるが、**不停止を計算し直すには連続していないと使えない。**
**丸めると、止まったかどうかが読めなくなる。**

したがって、次を**この決定とセットの条件**として扱う。**どれか1つでも欠けたら、この決定は採ってはならない。**

- **実走行の GPS ログをリポジトリにコミットしない**（`../../CLAUDE.md`）。テストは合成データ
- **走行単位で消せるようにする**（`rides` と `ride_points` を分けている理由）
- **公開の画面に生の点を出さない。** 出すのは**セル単位に丸めたもの**だけ
- **公開の画面で時刻も丸める。** セルだけでは足りない——
  **110m のセルと秒単位の時刻を時系列に並べれば、1人の走行経路が復元できる。**
  走る人が数人しかいないハッカソンの規模では、**これは実際に起こる**
  （`../interfaces/web-ui.md`「場所の詳細」）
- **走行中の近傍を保つ状態は、これとは別**である。あちらは Durable Object のメモリに置き、
  **D1 に書かない**（`0005-realtime-transport.md`）。**リアルタイム経路と蓄積を混ぜない**

**ハッカソンの期間と規模では、これで釣り合うと判断した。**
実利用に出すなら、保存期間の上限・取り下げの手段・同意の取り方が要る。
**やらないと決めただけで、要らないわけではない。**

もう1つ、軽い方の代償。**D1 の行数が増える。**
1Hz の測位なので、1時間の走行で 3600 行。**ハッカソンの規模では問題にならない。**

## 得るもの

- **しきい値を、データを集め直さずに調整できる。** 実走行が1回しかできなくても、
  そのログから何通りもの判定を試せる
- **指標を後から選べる。** 率で足りなければ件数へ、逆も自由
- **「検知」と「不停止」を別の概念として持てる**

## 見直す条件

- **D1 の行数か読み取り回数が問題になった**
  → 集計結果のテーブルを足す。**生ログは消さない**（作り直せることがこの決定の目的なので）
- **走行ログが集まらないと分かった**（実走行が数回で終わる）
  → **この決定は変えない。** 変えるのは指標の側で、
  `../interfaces/web-service.md` の「率で見る」を件数に切り替える。
  **生ログの保存は、データ量に関係なく不停止の再計算に効く**
- **実利用に出す判断をした**
  → **この決定を採り直す。** 保存期間・取り下げ・同意を先に決めること。
  **上の「セットの条件」だけでは足りない**
